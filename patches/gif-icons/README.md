# Home and dock GIF icons — build 660300

Based on 660299. Long-press a home/dock icon, use its existing Edit icon action, and choose **Choose animated GIF**. Each home launchable ID has its own selection. The original icon-picker path is still available; if a GIF is present the prompt makes clear that choosing a regular icon removes the GIF. The prompt also offers removal. Canceling the document picker leaves the old GIF intact. All Apps uses a different view and its editing request does not get the GIF option.

GIFs are copied into private launcher preferences, not retained via a temporary document permission. Each file is limited to 1 MiB and a GIF logical canvas of 512×512, and the total encoded GIF storage is limited to 16 MiB. Decoder errors and read/size/storage failures leave the previous icon in place. Playback uses Android Movie and a software-rendered ImageView, with frame callbacks gated by view attachment, visibility, window focus, visible rectangle, and the drawer panel. It is not intended to animate a drawer icon. Existing Picasso requests are canceled for a GIF-bound home view; non-GIF icons retain the native path.

GIF bytes are encoded in `sl_mod_settings`, included in the existing versioned mod-backup preference snapshot. The added host backup round-trip covers a GIF-shaped preference string, but real device backup/restore and whether native restore preserves every launchable ID are **not verified**. Existing backup limits still apply; this does not encrypt a backup. A new signing key was explicitly approved: build 660300 **cannot update 660299 in place** and uninstalling the old launcher can erase its data. Keep a separate backup and verify restoration before relying on it; backup/restore has not been tested on a phone. Preserve the new key outside Git for later builds.

## Rebuild and checks

Decode `SmartLauncher-SearchDialer-660299.apk`, run `python3 patches/gif-icons/apply.py <decoded>`, and build with apktool. The script moves the edited icon picker to classes4 because classes2 is already at its DEX reference limit. Append `patches/gif-icons/classes5.dex` to the built APK, align, then sign. The helper dex is built from `SLGifIcons.java` using Android 31 API jar, Java 8 bytecode, dx with min SDK 24; the included `yb6` stub is compilation-only and is **not** included in the helper dex. Disassembled helper smali is in `smali/` for inspection.

Run `GifValidationTest`, the mod-backup, search-dialer, and task-selection host tests, and `check_build.py <decoded-660299> <decoded-output>`. Alignment, v2/v3 signature and decoded structural checks passed; the checks confirm unchanged drawer, search, mod-backup hooks, manifest and resources. These checks do not run Android.

**No Android device or emulator was available.** Actual playback on Android versions and phone GPUs, picker interaction, animation when navigating or dragging, refresh after editing, memory/battery impact, accessibility, and backup/restore including ID mapping still require phone testing. The native Movie decoder and obfuscated launcher hooks may behave differently on particular devices. No claim of successful runtime testing is made.
