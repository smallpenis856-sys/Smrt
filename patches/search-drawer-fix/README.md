# Visible search transition and drawer top fade — 660306

Based on 660305. The earlier effect changed only the active glass by 8%, so it could be hard to notice; its one-shot pre-draw listener could also run before the search panel was visible. The drawer search bar now visibly closes toward its center by clipping its existing rendering over 180 ms; then the existing atomic drawer-to-search navigation runs. The active search bar reveals from its center over 280 ms. Text and icons retain their original sizes and do not stretch; the opening animation waits for a visible, laid-out panel, and the keyboard/search navigation is not otherwise changed. The approximately 180 ms close now intentionally precedes search navigation and keyboard focus. Home-originated searches get the opening part; drawer microphone launches voice search as before. Both animations obey Android's animator-duration setting. This is an approximation, not a copy of iOS or Samsung.

Rapid duplicate taps are ignored while closing. Detachment cancels the transition and restores prior clipping; if the drawer is no longer visible/focused, delayed navigation is not performed. Search-panel exit/detach removes a pending pre-draw listener, cancels the reveal and restores previous clip bounds. There is no continuous animation or backdrop capture.

In the highlighted All Apps grid, the app explicitly enabled a 24dp vertical fading edge. `GridRecyclerView` now returns zero strength for the top fading edge only, retaining the native bottom fade, existing status-bar insets, padding, search-bar glass, scrolling and interactions. This targets the visibly faded tops of icons; normal viewport clipping can still show a partial row while scrolling. No device was available to confirm this is the only cause of the screenshot issue.

`SearchDrawerFixTest` uses provided host stubs to check clipping, visible-frame wait, rapid taps, cancellation, focus, and restoration. `python3 patches/search-drawer-fix/check_build.py <decoded-660305> <decoded-output> <signed-apk>` verifies only the two intended native-class hooks changed, previous navigation body is retained, and other launcher smali, GIF helpers, menus and resources are unchanged. GIF, backup, dialer and task host regressions pass; alignment and v2/v3 signature verification pass. The signature matches 660304/660305; it differs from 660303 and earlier.

No phone/emulator was available: animation appearance, timing, mic, keyboard, back/no-flash navigation, icon appearance at different scroll positions, status insets, rotation, accessibility, battery use and update installation are not device-tested.
