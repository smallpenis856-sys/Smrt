# Launcher backup: mod + glass clock — build 660298

The user requested that the existing launcher backup also include Mod Settings and the Liquid Glass clock. They explicitly chose to include the launcher task list, interviews, expenses and WhatsApp templates too. The launcher already writes a ZIP `.slbk` using `xi0`/`h0` and unpacks it into a temporary directory during `yx0` restore, but the native backup registry only includes the launcher's main preference file, not these mod stores.

The ZIP writer now appends one versioned binary entry from `SharedPreferences.getAll()` snapshots of `sl_mod_settings` (including clock), `sl_agenda_prefs_v1` (glass switches) and `sl_agenda_panel_v1` (mod options and personal agenda data). The existing restore pipeline reads that entry after native preferences pass its validity check and restore stage. On older backups with no entry it leaves current mod stores untouched. For new backups it validates the entire entry before replacing those stores; a commit failure attempts rollback and reports an error. Standard booleans, integers, longs, floats, strings and string sets are preserved with size limits. A restore intentionally replaces the mod data with the snapshot, as launcher restore does for its configuration; this does not make the whole native restore transactional. The launcher restart after restore remains unchanged.

The backup contains private task, interview, expense, location and template information and is not encrypted by this patch. Store/share it accordingly. Existing backups cannot contain mod data retroactively. A file made with this build needs this or a later compatible build to restore the extra section; old launcher versions ignore it. The limit for this mod section is 32 MiB; exceeding it fails backup rather than dropping data.

## Rebuild and checks

Decode 660297; apply `h0.patch` and `yx0.patch` using `git apply --unidiff-zero`, copy `smali/SLModBackup.smali` to `smali_classes4/`, set versionCode 660298, build, align, and sign with the 660297 key. Java 8 + Android 31 + dx generate the included smali. Host tests compile the small Android interfaces in `stubs/` only for testing; they are not shipped. Run `SLModBackupTest`, `check_build.py` against decoded input and signed output, and prior regressions.

Host tests covered typed ZIP round-trip, empty old backups, malformed/truncated input without clearing data, and simulated commit-failure rollback. Signature, alignment and decoded structural regressions passed. No Android device was available: real backup/restore, UI error handling, preferences listeners, launcher restart, large archives and cross-version behavior remain unverified. In particular rollback is best effort, not a guarantee if storage fails. Keep a separate known-good backup before testing restore.
