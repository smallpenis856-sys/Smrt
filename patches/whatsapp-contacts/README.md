# WhatsApp contact search — build 660290

Based on the restored 660288 `SmartLauncher-AllAppsSearch-NoFlash.apk`, preserving all previous search, drawer and startup behavior. The existing `SLSearchHook.attach` inserts a separate, horizontally scrollable contact-results row between its existing cards and native results; the original editor, search list and cards remain intact. The launcher must already have contacts permission or the user can explicitly tap the row to grant it. The manifest already declares that permission. No network request is made by the launcher. Search starts after two characters, uses the Android contacts provider in a background worker after a 250ms debounce, and cancels stale queries on edits and detach. Up to five distinct phone numbers appear as tappable results.

Each result opens an explicit `whatsapp://send?phone=` intent in WhatsApp, falling back to WhatsApp Business. The launcher never reads WhatsApp messages, existing chat history or group chats, and cannot establish that a contact actually uses WhatsApp; the target app decides whether that number can be opened. Phone numbers are displayed before tapping. International normalized numbers are preferred; otherwise the device's SIM/network/locale country is used for Android's E.164 formatting. Ambiguous extensions, invalid or unformattable numbers are skipped rather than guessed. A number stored without country code can still be interpreted using the wrong region; edit the contact into international format if needed. Permission denial keeps native search working.

Run `SLWaPhoneTest`, `check_build.py <decoded-660288> <decoded-signed-output>`, and the existing all-apps-search checks with the expected version changed to 660290.
